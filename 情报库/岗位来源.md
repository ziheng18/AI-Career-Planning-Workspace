# 岗位画像来源与数据性质声明

## 请先读这段

本工作台的 11 个 AI 岗位族画像（`数据/岗位库.js`），**不是实时招聘数据**，而是课程实践用的**示例数据**。构造方法是：

1. 收集人工智能产业人才相关的公开报告与行业文章；
2. 把其中关于"岗位职责、能力要求、学历门槛、薪酬区间"的描述，**人工转写**为结构化数值（兴趣期望 0–100、能力要求 0–100、锚画像）；
3. 用于教学演示"如何把行业信息转成可计算的画像"这一方法本身。

因此：

- 数值是**描述性转写**，不是统计抽样结果，**不应被引用为求职决策依据或薪资谈判依据**；
- 薪酬区间为公开信息的粗略区间，随城市、公司、年份波动很大；
- 若用于真实求职，请以目标公司的当季招聘要求与招聘平台实时数据为准。

## 能力维度是怎么定的

能力八维（`数据/题库.js` 的 `BANK_ABILITY`）不是照搬任何单一模型，而是按**AI 岗位招聘要求出现的频次**归并：

| 维度 | 归并了哪些常见要求 |
|---|---|
| 数学与理论 | 线性代数/概率统计/最优化、论文推导能力 |
| 编程工程 | Python/C++、代码规范、Git、调试 |
| 数据与实验 | 数据清洗、实验设计、消融分析、统计分析 |
| 算法建模 | 问题到 ML 任务的转化、论文复现、模型改进 |
| 系统与部署 | 服务化、Docker、云平台、性能与稳定性 |
| 产品与业务 | 业务理解、指标定义、需求文档、成本意识 |
| 沟通表达协作 | 技术讲解、文档/论文写作、团队协作 |
| 自主学习与抗压 | 自主规划、长期无反馈工作的耐受度、求助与调整 |

## 岗位画像是怎么定的

每个岗位标注 1–3 个最契合的职业锚（施恩八锚），依据是该岗位**工作形态所奖励的价值取向**。例如：

- 算法研究员奖励"攻克难题"与"技术精深"→ `CH`（纯粹挑战）+ `TF`（技术职能）
- AI 产品经理奖励"推动事情"与"做新东西"→ `GM`（管理）+ `EC`（创业创新）
- 算法合规岗位奖励"稳定"与社会价值 → `SE`（安全稳定）+ `SV`（服务奉献）

这一映射是**教学用的简化判断**，不是心理学结论。个人与岗位的锚匹配度只是 15% 权重的方向性参考。

## 工作内容时间分配（workMix）是怎么定的

每个岗位还标注了 `workMix`：一周里「写代码/做技术、开会/对齐、写文档/报告、沟通协调」四项各占多少百分比，合计 100。

**这一栏是课程设计的重点**，因为它回答一个公开资料很难说清的问题：**这份工作实际把时间花在哪**。常见的认知偏差包括：

- 以为技术岗整天写代码，实际算法研究岗有约 40% 时间在写文档、读论文、产出结论
- 以为 AI 产品经理主要在想创意，实际约 35% 在开会、35% 在写文档
- 以为做工程就能训练大模型，实际多数岗位是把现成模型接进业务链路

**它替代了原先的"生涯人物访谈"**。访谈确实能拿到这些信息，但时间成本高、且学生不一定能找到合适的从业者，作为必做作业不合理。改成岗位库直接标注后，信息对所有人一致、可核对、不依赖人脉。如果学生自愿完成访谈，那是加分项，写进报告正文即可。

数值来源与上面的能力要求相同：对公开岗位描述、技术社区讨论与行业报告中的定性描述做结构化转写，属**课程示例数据**，反映的是常见情况而非某个具体公司。

## 如何自行更新岗位库

1. 打开 `数据/岗位库.js`，按现有格式增删岗位对象；
2. 必填字段：`id`、`name`、`family`、`summary`、`duties`、`interest`（6 维）、`ability`（8 维）、`workMix`（4 项，合计 100）、`anchor`、`minEdu`、`employers`、`salaryBand`、`risks`；
3. `interest` 与 `ability` 的取值为 0–100，**是"岗位期望水平"，不是"合格线"**——写成 100 会让所有候选人都匹配不上；
4. 保存后运行 `npm test`，`测试/契约.test.js` 会检查字段完整性、取值边界、锚引用合法性，以及 **workMix 四项是否合计 100**；
5. 若新增了岗位，记得同步更新本文件与 README 中的岗位数量表述。

> 契约测试的存在就是为了让"改数据"这件事不会悄悄破坏匹配计算。
