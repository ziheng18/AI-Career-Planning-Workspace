# AI 职业生涯规划学习实践工作台

面向**人工智能专业**本科生的课程实践作品。把"自我认知 → 行业认知 → 目标决策 → 能力锻造 → 行动追踪"做成一条**可量化、可追溯、可导出**的链路。

## 怎么用（30 秒上手）

1. **双击打开 `工作台.html`**（Chrome / Edge / Firefox 都行，无需安装任何东西，无需联网）
2. 想先看"填完之后是什么样"→ 点左侧「**载入示例档案**」，会问你要看**大一**还是**大三**的示例
3. 想从零开始 → 按左侧导航「1 总览」里的八步顺序走一遍，约 **60–90 分钟**
4. 填完到「8 导出报告」→ 可导出四份东西：**规划报告**（总结性文字，可打印为 PDF）、**原始数据**（CSV+JSON，供核查）、**档案 JSON**（备份续做）

> 数据只存在你自己浏览器的 `localStorage` 里，不上传任何服务器。换电脑请先导出档案 JSON，在新机器上导入。

## 依赖情况

**运行时零依赖。** 没有 `node_modules`、没有锁文件、没有 CDN、没有字体外链、不发任何网络请求（除了读取同目录下的图片素材）。整个应用就是「1 个 HTML + 1 个 CSS + 14 个 JS + 4 个素材」，共 23 个文件，可以直接拷进 U 盘或丢到任何静态服务器上。

| 用途 | 需要什么 |
|---|---|
| **运行工作台** | 一个现代浏览器。仅此而已 |
| **跑测试** | Node.js（`npm test`）。Node 只用于测试，不是运行时的依赖 |
| **导出 PDF** | 浏览器自带的打印引擎（Ctrl+P → 另存为 PDF）。没有引入任何 PDF 库 |

选这个技术路线的理由见下方「技术选型说明」——核心是**双击即用、断网可用**，所以不能有构建步骤，也不接受 CDN。

## 部署到 GitHub Pages

代码本身在 Pages 上可直接运行（已实测，见下），仓库里已经准备好所需文件：

| 文件 | 作用 |
|---|---|
| `index.html` | Pages 的入口页，自动跳转到 `工作台.html` |
| `.nojekyll` | 关掉 Jekyll。Jekyll 会跳过下划线开头的文件，对中文路径的处理也不可靠——本项目大量使用中文目录名 |
| `.gitignore` | 排除可再生的构建产物（PDF 预览、截图），但保留两份示例档案 |

**步骤**：

```bash
git init
git add .
git commit -m "AI 职业生涯规划工作台"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

然后在仓库 **Settings → Pages** 里把 Source 设为 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`，保存。等一两分钟，访问：

```
https://<你的用户名>.github.io/<仓库名>/
```

> **子目录部署不用改任何代码。** 应用里所有资源引用都是相对路径，且 `localStorage` 的键会带上仓库名做命名空间（GitHub Pages 下 `用户名.github.io` 的所有项目**共用同一个 origin，localStorage 不按路径隔离**——不加命名空间的话，两个项目会互相覆盖档案且没有任何提示）。

**部署前建议跑一遍**：

```bash
npm test              # 逻辑 + 界面（纯 Node，零依赖）
npm run test:http     # 起本地静态服务，用真实浏览器验证 HTTP 下的行为
```

`test:http` 专门验证 `file://` 与 HTTP 有差异的两处：**fetch 相对路径**（打印视图要把封面图转成 base64）与 **window.open**（打印视图）。这两条只看代码看不出来。

**关于中文文件名**：项目的目录与文件名大量使用中文（`数据/`、`界面/`、`工作台.html`），GitHub Pages 会把它们转成百分号编码（`%E5%B7%A5%E4%BD%9C%E5%8F%B0.html`）。已用模拟 HTTP 服务实测：中文路径返回 200、`.js` 的 `Content-Type` 正确、应用完整加载。浏览器里一切正常，只是地址栏看起来编码过。

## 工作台的七个部分

| # | 部分 | 用户要做的事 | 产出 |
|---|---|---|---|
| 1 | 总览 | 看流程与进度 | — |
| 2 | 基本信息 | 年级、专业方向、GPA 档位、是否读研（只有 4 项） | 门槛条件 + 作答口径 |
| 3 | 兴趣测评（36 题） | 霍兰德 RIASEC，1–5 级量表 | 兴趣六边形 + 三字母代码 |
| 4 | 职业锚（40 题） | 施恩八锚，1–5 级量表 | 主锚 / 副锚 / 双锚判定 |
| 5 | 能力清单（48 项） | **勾选式**：勾你"能独立做到"的行为项，题目随年级切换 | 能力八维 + 可选证据 |
| 6 | 决策输入 | 岗位偏好、6 项标准排序、6 条路径打分、每周可投入时长、期望城市 | 权重 + 路径评分 |
| 7 | 结果 / 行动 / 导出 | 查看量化结果、生成行动计划、看逐年规划建议、导出 | 报告 + 原始数据 + 档案 |

> **关于生涯人物访谈**：v0.2 已移除。原因很实际——它的时间成本高，而学生不一定能找到合适的从业者，作为必做作业不合理。
> 它原本要回答的两个问题（这份工作实际在做什么、实际代价是什么）改由**岗位库直接承担**：
> 每个岗位都标注了「一周工作内容时间分配」，报告会自动生成**排名较高职业的简表**，
> 对所有人一致、可核对、不依赖人脉。

> **关于能力部分为什么不用自评量表**（v0.3 改动）：1–4 档自评给一个 62 分，学生既不知道 62 分离面试有多远，
> 也没法反驳这个数字。现在换成**行为清单勾选**：每维 6 项、由易到难排列，每一项都是可核验的具体行为。
> 勾选即证据，没勾上的部分直接就是学习任务。每维还可选挂一条证据（成绩、仓库链接、实习证明），
> 报告会据此标记哪些维度「已印证」、哪些「仅自评」。

> **关于逐年规划建议**：行动计划页的任务清单回答"这几个月做什么"，但看不见"三年后想站在哪里"。
> 这一栏由 `CP.yearPlan` **实时算出来给用户看**，不是让用户填的——职业规划的远期部分，
> 学生最缺的不是"写下来的地方"，而是"每个阶段该做什么"的判断，给一张空白框只会写出"我要努力"。
> 每一条都锚到**具体学年**（大几 / 研几），起点取本人当前年级，已经过去的学年不出现，
> 并随主路径调整侧重。因为它必须跟着年级与路径变，所以**不存进档案**。

## 年级是关键变量

工作台把"大一"和"其他年级"当作**两种不同的规划问题**来处理，因为同一个分数对两者的含义不同。

| 事项 | 大一 | 大二及以上 |
|---|---|---|
| 能力清单题目 | 48 项，问"接触与理解" | 48 项，问"实际做到过什么" |
| 第 1 项门槛 | 刻意放低（"我知道机器学习大概是怎么回事"） | 也放低（"能读懂别人写的代码"） |
| 适配度权重 | 兴趣 **0.65** / 能力 0.22 / 锚 0.13 | 兴趣 0.40 / 能力 **0.45** / 锚 0.15 |
| 差距任务排序 | 按**与兴趣方向的贴合度**，并先安排一次方向探索 | 按缺口严重度 |

**为什么**：大一清单勾得少，多半只是"还没学到"，拿它主导排序会得出"你什么都不适合"。而兴趣相对稳定，且大一最该做的事是顺着兴趣把方向定下来——**对什么感兴趣之后，学习的时间还有很多**。

## 量化模型（一句话版）

```
兴趣向量 I(6维) · 职业锚 A(8维) · 能力向量 S(8维) · 决策权重 W(6维)
        ↓ 兴趣/锚：Likert 归一化到 0–100；能力：勾选式加权 Σ已勾权重/Σ全维权重
岗位适配度  Fit   = w_i×兴趣匹配 + w_a×能力适配 + w_n×锚对齐   （权重随年级切换）
路径加权得分 Path = Σ 权重_i × (我的评分_i / 5) × 100
        ↓
Top3 岗位推荐 + 差距学习任务 + 主路径 / Plan B
```

三条设计红线：

- **只惩罚不足，不惩罚过剩**——某项能力远超岗位要求不加分，因为招聘不是这么运作的。
- **缺口平方惩罚（软最小值）**——核心能力差 30 分，比三处各差 10 分严重得多。
- **兴趣封顶**——达到岗位期望即满分，避免"兴趣越极端越匹配"。

完整公式与推导见 [文档/数据字典.md](文档/数据字典.md)。页面上每一个分数都能点开「**查看推导**」，看到用了哪几道题、什么权重、怎么算出来的。

## 视觉素材是怎么来的

工作台里的两张配图（首页主视觉、报告封面）由**你本机的 ComfyUI + Qwen-Image-2.1** 生成，脚本在 `素材/`：

```powershell
# 需要本地 ComfyUI 正在运行（默认 127.0.0.1:8188）
pwsh -File 素材/批量生成.ps1        # 重新生成全部素材
pwsh -File 素材/生成图.ps1 -Name my-img -Prompt "..." -Width 1024 -Height 1024
```

三条使用约定：

1. **图里不放文字。** Qwen-Image-2.1 不能可靠地渲染文字，写英文也会糊。所有文字都由 HTML 渲染——这样可访问、可搜索、可换语言，打印也清晰。
2. **图只作装饰，不承载数据。** 图表全部是代码生成的内联 SVG（`界面/图表.js`）。数据图一旦变成图片，就无法重算、无法核查、打印会糊。
3. **精细几何自己画。** 试过让模型生成"极淡的雷达底纹"，结果是近乎空白——模型做不了这种精确控制。这部分改用 `素材/雷达底纹.svg`，几何精确、只有 1KB。

素材与你本机的对应关系：模型 `qwen-image-2.1-Q4_K_S.gguf` + 文本编码器 `qwen3vl_8b_w4a8.safetensors` + `qwen_image_2.1_vae_bf16.safetensors`，走 `UnetLoaderGGUF` + `CLIPLoader` + `TextEncodeQwenImage21`。1024×1024 / 15 步约 107 秒（RTX 5060 8GB）。

> **为什么代码不用框架、图表不用图表库**：为了保持"双击即用、断网可用"。图表由代码绘制为内联 SVG，打印成 PDF 时矢量清晰，而且数据变了图就能重算——不会变成一张"死图"。

## 响应式与移动端

窄屏（≤900px）下侧栏会变成**抽屉**：顶部一条顶栏（汉堡按钮 + 当前页名 + 进度），点开从左滑出，点遮罩 / 点关闭 / 按 Esc / 点任一导航项都会收起。

| 断点 | 变化 |
|---|---|
| ≤900px | 侧栏改抽屉；网格转单列；顶栏出现 |
| ≤860px | 首页主视觉图铺满并降低不透明度，标题回归普通流 |
| ≤760px | 测评量表改成整行铺开的等宽按钮（4 档与 5 档列数不同），点击热区 40px |
| ≤700px | 宽表格改为卡片堆叠（用单元格的 `data-label` 带出表头） |
| ≤620px | 标题与副标题缩小一档 |

两处需要说明的实现选择：

- **图表在窄屏换排版，而不是缩放。** 缺口图 560px 宽直接缩到 320px，11px 的字会变成约 1.5mm，读不了。所以窄屏改用 `CP.chartGapsCompact`（单条 + 缺口标注），字号保持原尺寸。
- **关闭的抽屉要 `inert`。** 只做 `visibility: hidden` 挡不住键盘 Tab 跑进屏幕外的抽屉里，所以 `applyDrawerState()` 会同步 `inert` 与 `aria-hidden`。这部分纯 CSS 做不到，必须由 JS 打状态。

无障碍方面：量表按钮带 `aria-label`（"第 4 档：比较符合"）与 `aria-pressed`；抽屉按钮带 `aria-expanded`/`aria-controls`；尊重 `prefers-reduced-motion`。

## 技术选型说明

| 项 | 选择 | 理由 |
|---|---|---|
| 运行方式 | `file://` 直接打开 | 课程实践场景，零部署 |
| 前端 | 原生 HTML/CSS/JS，无框架 | 无 CDN 依赖，离线可用 |
| 模块化 | IIFE + 全局 `CP` 命名空间 | 浏览器 `<script>` 与 Node `require` 双兼容，同一份逻辑代码可被测试直接加载 |
| 图表 | 手写内联 SVG | 不依赖图表库；矢量输出；数据可重算 |
| 存档 | localStorage + JSON 导入导出 | 无需后端；可携带、可交给教师核查 |
| 报告 | **PDF 为默认交付**（打印视图 + 浏览器「另存为 PDF」），Markdown 作为可二次编辑的备选 | 不引入 DOCX/PDF 生成库，避免破坏"双击即用、离线可用"的前提；浏览器自带的 PDF 引擎排版质量足够，且矢量输出 |

## 运行测试

```bash
npm test                 # 逻辑层 107 项 + 界面层 84 项（零依赖，纯 Node）
npm run test:logic       # 只跑逻辑层
npm run test:ui          # 只跑界面层
npm run test:browser     # 真实浏览器诊断（无头 Edge/Chrome，桌面视口）
npm run test:mobile      # 真实浏览器诊断（窄屏视口 420×860）
npm run test:touch       # 真实触摸诊断（CDP Input.dispatchTouchEvent，移动端仿真）
npm run test:pdf         # 真正导出 PDF 并校验分页、配色、空白页、章节齐全
npm run test:http        # 起本地静态服务，验证 HTTP 部署下的行为
npm run test:all         # 上面全部
npm run demo             # 重新生成示例档案
```

五个层次：

- **逻辑层测试**（107 项）：契约与数据完整性、年级口径切换、归一化与 base、反向计分、一致性与计时检验、霍兰德/锚判定、兴趣封顶、软最小值、锚对齐、学历门槛、路径权重、幂等性、极端档案、大一模式专项，以及**架构约束**（导出层不得依赖界面层）。
- **界面层冒烟测试**（84 项）：用一个最小 DOM 仿真把 `工作台.html` 里的 14 个脚本按真实顺序加载并真实触发点击。外壳 DOM 是**直接解析 `工作台.html` 的 `<body>`** 得到的，不是手工复刻——否则改 HTML 会导致假失败。
- **浏览器诊断**（`test:browser` / `test:mobile`）：用无头 Edge 打开工作台的真实副本，做 `elementFromPoint` 命中测试、计算样式检查，以及**在坐标上派发真实事件**的指针级点击。
- **触摸诊断**（`test:touch`）：走 Chrome DevTools 协议（`Emulation.setTouchEmulationEnabled` + `Input.dispatchTouchEvent`），做真机式的触摸点击。**这一层才发现了 × 点不动的真正原因**——合成鼠标点击会"全绿"，因为 `.click()` 与 `elementFromPoint` 都不反映触摸时元素的实时位置。
- **PDF 校验**（`test:pdf`）：用 `Page.printToPDF` 真正导出一份 PDF，再解压页面内容流，检查分页、空白页，以及**品牌色是否真的写进了 PDF**。这一层抓到了"打印视图缺设计令牌导致图表全黑"——那个 bug 在网页面里完全看不出来。

> **测试边界**：这些测试覆盖布局、命中、交互与打印输出，但不判断视觉是否好看（间距、配色、观感）；那部分仍需人工确认。

## 导出

**主交付物是一份 PDF**（A4、封面 + 五章正文 + 计算口径附录，含图表）。三种拿到它的方式：

**① 工作台内（推荐给学生）**

工作台 →「导出报告」→ 点主卡片上的「生成可打印页面」→ 新页面按 **Ctrl+P**（Mac 为 **⌘P**）→ 打印机选「**另存为 PDF**」，纸张 A4。

排版已经处理好：每章从新页开始、表格跨页重复表头、卡片与提示框不会被从中间截断、图表与表头配色完整保留。

**② 命令行（教师出样例 / 批量核查）**

```bash
npm run test:pdf        # 生成 输出/报告预览.pdf，并校验分页、配色、章节齐全
```
脚本会顺带输出 `报告预览-封面.png`、`报告预览-表格.png`（分章截图）、`报告预览-版面.png`（前两页长图）。

**③ 从 PDF 里核对内容**

PDF 里的中文是字形编号 + ToUnicode 映射，直接 grep 字节流搜不到任何中文——要确认某章节是否真的进了 PDF，只能用这个工具解码。

## 已知坑（改代码前请先读）

| 坑 | 症状 | 原因与对策 |
|---|---|---|
| `inert` 必须按断点区分 | 宽屏下侧栏整条点不动 | `applyDrawerState()` 只在 `matchMedia('(max-width: 900px)')` 命中时才允许设 `inert`。宽屏侧栏常驻，设了 `inert` 等于禁用整个导航 |
| 抽屉打开不能有位移动画 | 开完立刻按 × 点不到 | 滑出期间按钮还在视口外（0.24s 时 `left=-46`）。`.sidebar.open` 用 `transition: none` 瞬时到位；关闭时才播动画 |
| 窄屏图表不能靠缩放 | 手机上图表文字读不了 | 560px 宽的图缩到 320px，11px 字变约 1.5mm。窄屏改用 `CP.chartGapsCompact` 换排版而非缩放 |
| 弱断言会骗过自己 | "命中测试通过"但实际点不到 | `elementFromPoint` 与 `el.click()` 都不反映触摸时的实时位置与 pointer-events。关键交互必须用 CDP 真实触摸验证，并断言"操作后的状态"而不只是"能命中" |
| 异步收尾在无头环境下不可靠 | 诊断工具输出为空 | `--virtual-time-budget` 下 `setTimeout`/`requestAnimationFrame` 不保证跑完。诊断探针改为每个阶段**同步**写入 `#diag` |
| 打印视图必须自带设计令牌 | 导出 PDF 里图表全黑、色带消失 | 图表用 `fill="var(--brand)"` 取色，而打印视图是**独立文档**，不继承 `样式/工作台.css` 的 `:root`。`renderPrintView` 必须重新声明色板，并开 `print-color-adjust: exact` |
| 假 DOM 要按真实 HTML 建 | 改 HTML 后测试大面积假失败 | `buildDom()` 直接解析 `工作台.html` 的 `<body>` |
| 可选 API 缺失不能拖垮启动 | 保存/导入/重置全部失效 | `bindGlobal()` 里 `document.addEventListener`、`matchMedia`、`window.addEventListener` 都做了能力检测 |
| PDF 的"页"不能靠猜 | 页数与文本量算错，误判成"章节没进 PDF" | PDF 里混着字体子集流（解压后 1.2MB、恰好含 8 个 `Tj` 字节）与图片流。必须按**页对象 `/Contents` 的引用关系**挑内容流，不能靠"流里像有文字"来猜 |
| PDF 里的中文搜不到 | grep 字节流找不到章节标题 | PDF 存的是字形编号 + ToUnicode 映射。核查章节只能解码，工具见 `测试/PDF取文.cjs` |
| 日期不能走 `toISOString()` | 凌晨算出的"今天"是昨天，当天到期的任务被判逾期 | `toISOString()` 转的是 UTC。东八区本地 00:00–08:00 之间 UTC 仍在前一天。统一用 `CP.dateOnly()` / `CP.parseDateOnly()` 按本地时区取值 |
| 勾选式清单必须记时间戳 | 秒勾全表检测不到 | 清单不做题内一致性检验，**作答时长是它唯一的质量信号**。漏记 `t` 会让 `timingCheck` 直接跳过 |
| 示例数据不要写死时间 | 换年份打开示例全表逾期；作答时间戳停在两年前 | 示例的日期与**毫秒时间戳**都按"相对今天"生成。审计时容易只查 `YYYY-MM-DD` 字面量，漏掉 `1700000000000` 这类常数 |
| 显示时间必须转本地 | 首页时间比真实时间少 8 小时 | 档案按惯例用 `toISOString()` 存 UTC，界面要显示墙上时间。统一走 `CP.localTime()`，不要 `.slice(0,16).replace('T',' ')` |
| 勾选式块不能按"全勾"算完成 | 诚实作答的学生侧边栏永远不显示完成 | 能力清单的门槛是**每维至少 1 项**（`CP.blockProgress`），不是 48 项全勾。进度、侧栏打勾、完整性校验必须共用这一个判据——曾经进度看数量、校验看门槛，出现"校验通过但侧栏未完成"的自相矛盾 |
| 勾选式清单的计数不能带分母 | 显示 `7/48` 会暗示"要做完 48 项" | 与上一条同源：分母是"要求"的暗示。勾选式只报 `已勾 N 项`；Likert 题才报 `已答/总题数`（那里分母确实是要求）。判据是 `threshold < total` |
| 假 DOM 的三个隐藏缺口 | 断言恒真、读不到文本、读不到条宽 | `textContent` 必须聚合后代；`style` 必须真读写 `style` 特性（否则 `style.width !== '0%'` 恒真）；`checked`/`value` 要反映特性。缺一个就会放过真 bug |
| 假 DOM 的选择器引擎要懂组合符 | 断言结论与真实浏览器不符 | `>` / `+` / `~` 必须实现；曾经把 `>` 直接 filter 掉，`.yearplan > li` 退化成后代匹配，把嵌套的 li 也算了进来。**另外组合符记在链的左侧元素上**，读错位一格就静默退化。已加 5 条基础设施测试守着 |
| 建议不能依赖"用户可能没填"的输入 | 系统凭空断言"你该走研究路线" | 路径评分不填时六条路径默认分几乎并列（81.0 / 80.0 / 73.3 / 72.4），主路径实际由数组顺序决定。逐年规划的侧重改看**首位岗位的学历门槛**（实测结果） |
