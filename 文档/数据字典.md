# 数据字典与算法口径

本文件是工作台的**唯一权威口径说明**。修改 `数据/schema.js` 的数据契约时，必须同步修改本文件，并更新 `测试/契约.test.js`。

契约版本：`1.0.0`　存档类型：`ai-career-workbench/archive`

---

## 一、档案结构（Archive Schema）

一份档案 = 用户全部原始作答 + 决策输入 + 计算结果快照。导出为 `职业生涯规划档案-*.json`。

```jsonc
{
  "kind": "ai-career-workbench/archive",   // 文件身份标识，导入时校验
  "schemaVersion": "1.0.0",
  "createdAt": "ISO 时间", "updatedAt": "ISO 时间",

  // 只保留四项。城市与每周时长属于"决策输入"而不是身份信息，已移入 decision。
  "profile": {
    "grade": "大三",              // 大一|大二|大三|大四|研一|研二|研三
    "track": "人工智能",
    "gpaBand": "10-30%",         // 大一不适用，页面会禁用该字段并清空此值
    "acceptPostgrad": "接受"      // 本页唯一参与计算的一项：筛选学历门槛
  },

  "answers": {
    // { 题号: { v: 原始分, t: 作答时间戳(ms) } }；原始值永不改写，反向计分在计算层处理
    // { 题号: { v, t } }；v 的含义由题库的量程决定
    "riasec":  { ... },   // 36 题，不区分年级。v = Likert 原始分 1-5
    "anchor":  { ... },   // 40 题，不区分年级。v = Likert 原始分 1-5
    "ability": { ... },   // 勾选式：v = 1 表示勾上，未勾则不写入。题目随年级切换（见第三节）
    "prefer":  {}
  },

  // 能力证据（可选）：每个能力维度挂一条最代表性的证据
  // 用途：报告里标记「已印证 / 仅自评」，并作为作品集台账素材。不填也能出结果
  "abilityEvidence": { "math": "线性代数 92 分" },

  "decision": {
    "jobPref": { "ai-pm": "like" },            // like|neutral|exclude
    "criteriaOrder": ["interest","growth",...], // 长度为 6 才算"已排序"
    "pathScores": { "p-考公": { "balance": 5 } }, // 只存被用户改过的格子
    "targetCities": ["杭州"],                   // 期望工作城市，仅展示，**不参与任何计算**
    "hoursPerWeek": 10                          // 每周可投入时长，用于把缺口换算成排期周数
  },

  // 生涯人物访谈已于 v0.2 移除。它原本承担的两个作用改由岗位库承担：
  //   "这份工作实际在做什么" → job.duties + job.workMix（一周工作内容时间分配）
  //   "实际代价是什么"       → job.risks + job.workMix
  // 移除的理由：访谈时间成本高，且学生不一定能找到合适的从业者，不适合作为必做作业。

  // 逐年规划建议**不进档案**：它是系统按"当前年级 + 主路径"算出来的建议，
  // 不是用户填的内容，所以由 CP.yearPlan 每次实时生成，见 逻辑/建议.js。

  // 行动计划看板
  "actions": [ { "id","title","due","status","evidence","fromGap","note" } ],

  // 复盘记录：只记可核对的事实（计划/完成/逾期/证据）与下一步
  "reviews": [ { "date","type","planned","done","overdue","evidence","next" } ],

  "computed": { ... }   // 结果快照，可随时被重算覆盖，不作为真相来源
}
```

**字段设计要点**

- `answers` 永远保留**原始作答**（含反向题的原始值）与**作答时间戳**。这样教师可以核查任一结论，也能通过时间戳做作答质量判断。
- `decision.pathScores` 只存**被用户改过**的格子，未改的用 `数据/路径库.js` 的默认值。界面上改过的格子里边框会变主题色，便于区分"我的判断"和"参考值"。
- `computed` 是缓存，不是数据源。任何输入变化都会把 `computed` 置空，下次访问结果页时重算。

**关于自由文本：全档案只有一处，且不参与计算**

早期版本的"其他客观限制""访谈关键信息""复盘进展/偏差/调整"都是主观题，无法量化，只能被原样复述进报告——那是把填空当成了分析，已在 v0.2 全部替换为可枚举或可计数的事实字段。

后来只剩一个合理的例外：`abilityEvidence`（每维一条可核验的凭据：成绩、仓库链接、实习证明）。它不是感受，也不参与打分，只用于在报告里标记该维度"已印证 / 仅自评"，并作为作品集素材。

**任何进入适配度、路径得分或缺口排序的字段，全部是可量化的枚举/计数/评分。**

### 逐年规划建议为什么不进档案

`CP.yearPlan(archive, decision, match)` 每次实时生成，**不存进档案**，原因有两条：

1. **它不是用户填的内容。** 它是系统给出的建议，存在档案里会让人误以为"这是我写的"。
2. **它必须跟着输入变。** 年级或主路径一改，整份安排就该重算；如果存成快照，改了年级却看到旧安排，那是错的。

起点取本人当前年级——大一看到四年，研一只看到研一以后，**已经过去的学年不出现**（对研一学生说"你大四应该……"是没有意义的）。

同一学年在三条主线下的侧重不同，用后缀点出来，而不是为六条路径写六份表：

| 主线 | 附加提示 |
|---|---|
| 考公（`p-考公`） | 每条都提示"行测与申论要提前一年启动" |
| 研究型（保研 / 出国 / 考研转行业） | 大二、研一、研二提示"优先保证科研产出，而不是刷实习数量" |
| 其他（直接就业 / 创业） | 大三提示"实习优先级高于课程分数，但不要挂科" |

另外，凡是大四年级那一条，都会附上"目标岗位可锁定「岗位匹配第一名」这类方向"。

## 二、归一化（第 0 层）

所有作答统一映射到 **0–100**。

| 原始题型 | 取值范围 | 公式 |
|---|---|---|
| Likert（兴趣、职业锚） | 1–5 | `norm = (raw − 1) / 4 × 100` |
| **能力清单（勾选式）** | 每项 0/1 | 见下方"能力清单计分" |
| **反向计分题** | 1–5 | 先取 `raw' = (max + min) − raw`，再按上表归一化 |

- 反向题在题库中用 `reverse: true` 标记，界面**不提示**哪些是反向题（否则会污染作答）。**只有兴趣与职业锚有反向题**——能力清单全部正向编码，不需要靠反向题检测直线作答。
- Likert 维度得分 `= 该维度全部已答题目 norm 的算术平均`；未作答的题不计入，也不按 0 分计。

### 能力清单计分（勾选式）

能力部分不是量表，而是**行为清单**：每维 6 项，按由易到难排列，勾选"我能独立做到"的项。

```
维度得分 = 100 × Σ(已勾项的权重) / Σ(该维全部项的权重)
```

| 项序号 | 1 | 2 | 3 | 4 | 5 | 6 | 合计 |
|---|---|---|---|---|---|---|---|
| 大二及以上权重 | 12 | 15 | 17 | 18 | 19 | 19 | 100 |
| 大一权重 | 14 | 15 | 16 | 17 | 19 | 19 | 100 |

**权重为什么递增**：等权会让"修完一门课"（大致对应 2 项）只拿到 33%，区分度不够。递增权重下，入门约 35 分、完整项目约 60 分、实习独立负责约 85 分——与旧版 1–4 档量表的档位大致对齐，所以匹配层的口径不用改。

**未勾的项计 0 分**，但两套清单的第 1 项门槛都刻意放得很低（"我知道这个说法" / "我能读懂一段 50 行代码"），所以正常填答的人不会掉到 0 分。这是勾选式量表唯一需要小心的地方，测试里有专门断言守着。

**为什么不再用 1–4 档自评**：自评量表给一个 62 分，学生既不知道 62 分离面试有多远，也没法反驳这个数字；而清单每一项都是可验证的行为，勾选即证据，没勾上的部分直接就是学习任务。

作答质量检测也相应改为看**勾选模式**（`CP.checklistCheck`）：

| 模式 | 含义 |
|---|---|
| 8 维全部勾满 | 清单含"能带新人上手""能设计出比基线更好的方法"这类项，正常学生不可能全具备 → 提示可能高估 |
| 每维都只勾第 1 项 | 没有做任何区分，等于没认真看 → 提示结果会很粗糙 |
| 勾了靠后的项却漏了第 1 项 | 清单是由易到难排的，通常意味着漏看 → 提示确认 |

## 三、年级决定的四件事

这是本工作台最容易踩坑的地方：**同一个分数字，对不同年级含义不同**。所以年级会切换四件事。

| 事项 | 大一 | 大二及以上 |
|---|---|---|
| ① 能力清单的题目 | 大一版 48 项：问"接触与理解"（"我知道机器学习大概是怎么回事"） | 大二及以上版 48 项：问"实际做到过什么"（"能复现一篇论文或一个开源模型的结果"） |
| ② 能力清单的计分 | 同上（勾选式加权），两套都用 `Σ已勾权重 / Σ全维权重 × 100` | 同上 |
| ③ 适配度权重 | 兴趣 **0.65**、能力 0.22、锚 0.13 | 兴趣 0.40、能力 **0.45**、锚 0.15 |
| ④ 差距任务排序 | 按"与兴趣方向的贴合度"排，并额外插入一条**方向探索**任务在最前 | 按缺口严重度排 |

> 大一的"能力清单"仍然是一份**进度记录**而不是能力评分：项都是"知道 / 跟做过 / 独立做过一次"这一档，没勾上通常只代表还没学到。所以它在适配度里只占 0.22。

**为什么切换年级会清空能力作答**：两套口径共用题号（`math1` 等）但题目不同，混在一起会让维度得分没有意义。所以界面在检测到年级变化时直接清空并提示重做。

**相关实现**：`数据/题库.js` 的 `CP.BANK_ABILITY.activeItems / scaleFor`、`逻辑/计分.js` 的 `CP.normItem`（base 参数）、`数据/schema.js` 的 `CP.fitWeightsFor`、`逻辑/建议.js` 的 `CP.gapPriority / CP.dimInterestFit`。

## 四、数据质量检验（第 1 层）

这两项检验的目的是**把不确定性显式暴露出来**，而不是假装测评都是准的。

### 3.1 一致性检验（识别直线作答）

```
若 某维度题数 ≥ 5 且 已答满 且 题内标准差 < 8
   → 标记"作答过于集中，本维度可信度低"
```

- 阈值 `8`：在 0–100 尺度上，标准差小于 8 意味着六七道题的选择几乎没有差异。
- 为什么要求 `题数 ≥ 5`：**只有兴趣与职业锚**用一致性检验，它们每维 6 题、5 题，样本足够；能力清单是勾选式，没有"题内方差"这个概念，改用 `checklistCheck` 看勾选模式。
- 有意思的一点：**如果一个人对所有题都勾同一个数字**，含反向题的维度反而会算出很大的标准差——这正是反向题的作用。真正被识别为"直线作答"的是"正向题全选 4、反向题全选 2"这种机械填法。

### 3.2 计时检验（识别快速作答）

```
每题平均秒数 = (最后作答时间戳 − 最早作答时间戳) / 1000 / 已答题数
若 < 3 秒 → 标记"疑似快速作答"
```

### 3.3 置信度提示（防止被算法支配）

```
margin = Fit(第 1 名) − Fit(第 2 名)
若 margin < 5 → 页面提示"前两名非常接近，请自行决断，不要盲从排序"
```

## 五、岗位适配度（第 2–4 层）

### 4.1 兴趣匹配（带候选归一化）

```
interest(job) = 100 × Σ_k [ w_k(job) × min( I_user[k] / r_k(job), 1 ) ] / Σ_k w_k(job)
```

- `w_k(job)` = `r_k(job)`：岗位对第 k 类兴趣的期望水平本身就是权重（越看重，权重越大）。
- `min(·, 1)` **封顶**：达到岗位期望即满分，超出不额外加分。

> **为什么不直接用余弦相似度**：余弦只看"形状"，不看"水平"。用它会导致"兴趣越极端越匹配"——一个把所有兴趣都打满分的人，会和所有岗位都很像。封顶 + 加权对齐才能表达"这个岗位看重 I，你 I 很强，所以匹配"。

### 4.2 能力适配（软最小值 / 缺口平方惩罚）

```
gap_k      = max(0, req_k(job) − S_user[k])       // 只惩罚不足，不惩罚过剩
ability(job) = 100 × Σ_k [ ω_k(job) × (1 − gap_k/100)² ] / Σ_k ω_k(job)
```

- `ω_k(job)` 默认等于 `req_k(job)`（要求越高的维度权重越大），可用 `abilityWeight` 字段单独覆盖。
- **平方的作用**：单点大缺口比分散小缺口惩罚更重。
  - 缺口 50 分 → 保留系数 `0.5² = 0.25`
  - 缺口 25 分 → 保留系数 `0.75² = 0.5625`
  - 即"一处差 50"比"四处各差 12.5"更吃亏。这符合招聘现实：算法岗数学不行，无法用别的优点补偿。
- **未作答按完全不足处理**（`got = null` 时视作 gap = req），因为"没答"通常等于"没有这项能力"。这是保守取法，会压低适配度而非抬高。

### 4.3 职业锚对齐

```
anchor(job) = 100 × Σ(命中得分) / 1.5

主锚命中岗位锚画像首位 → 1.0；命中第 2/3 位 → 0.5；未命中 → 0
副锚同规则，但整体权重 × 0.5
满分基准 = 主锚 1.0 + 副锚 0.5 = 1.5
```

因此实际可达到的锚对齐分数为：66.7（主锚首位 + 副锚不相关）、83.3（主锚首位 + 副锚次位）、100（主锚首位 + 副锚首位）、33.3（主锚次位 + 副锚不相关）等。

### 4.4 综合适配度

```
Fit(job) = w_i × interest + w_a × ability + w_n × anchor
```

| 年级 | w_i（兴趣） | w_a（能力） | w_n（锚） | 取值理由 |
|---|---|---|---|---|
| 大一 | **0.65** | 0.22 | 0.13 | 能力项此时普遍是"没接触"，拿它主导排序既不准也没用；兴趣相对稳定，且大一的任务是把方向定下来 |
| 其他 | 0.40 | **0.45** | 0.15 | 能力可改变、且招聘实际卡的就是它；兴趣决定长期能否坚持；锚对齐作方向性微调 |

权重之和恒为 1（`测试/契约.test.js` 与 `测试/匹配.test.js` 有断言）。

排序保留 2 位小数，展示时取整。分差小于 0.005 时按 `jobId` 字典序稳定排序，保证**同一档案的计算结果幂等**。

### 4.5 门槛筛选（不参与打分）

以下情况**直接排除**岗位，不进入打分：

| 条件 | 说明 |
|---|---|
| `岗位 minEdu > 我的可达学历` | 可达学历 = 当前学历；若 `acceptPostgrad ≠ 不接受`，则取 `max(当前, 硕士)` |
| `jobPref[job] === 'exclude'` | 用户明确排除 |

> **城市不参与筛选。** 岗位库未逐岗标注城市，而且"愿意去哪个城市"是用户的倾向而非门槛；强行按城市过滤只会让用户连结果都看不到。城市信息仅在结果页展示、在报告里作为参考记录。
>
> 排除是"门槛筛选"，不是"你不适合"。结果页会把被排除的岗位和原因单独列出来，用户可以回上一步调整条件。

### 4.6 可解释性输出

每个岗位结果都附带：

- **主要贡献项 Top3**：`ω_k × (1 − gap_k/100)²` 降序，归一化为百分比
- **主要拖累项 Top3**：只取 `gap_k > 0`，按 `ω_k × (gap_k/100)²` 降序
- **完整推导表**：兴趣逐维达成率、能力逐维缺口与贡献、锚命中判定

## 六、路径决策（第 4 层）

用户已经亲手给每条路径的每项标准打了 1–5 分，所以路径得分是**凸组合**，不需要相似度函数。

```
权重：w_i = (6 − 名次_i) / Σ_j(6 − 名次_j)，Σw = 1
      （第 1 位权重 6/21 = 28.6%，第 6 位 1/21 = 4.8%）
      （未完成排序时退化为等权 1/6 —— 不在用户未表达偏好时替他排优先级）

路径得分 PathScore(p) = Σ_i w_i × (Pref_p,i / 5) × 100
```

**一致性检查**：把"用户在最重要标准上打分最高的路径"与"加权总分第一的路径"比对。不一致时会提示——

> 你在最重要的标准「X」上给「A 路径」打了最高分，但它不是总分第一。这通常意味着你心里其实更想要另一条路，只是被其他标准拉低了总分。

这是为了对抗一个常见失败模式：**权重设置与真实偏好脱节**，导致算出一个用户其实并不想选的结果。

## 七、报告生成：从"数据汇总"到"结论文件"

报告（`导出/报告.js` 的 `renderPrintView` 为主、`toMarkdown` 为备选）**只写结论与依据**，过程性数据全部外置。

| 内容 | 是否进报告 | 去向 |
|---|---|---|
| 结论性叙述（摘要、兴趣/锚/能力的解读、匹配结论、路径比较） | ✅ | 正文 |
| 职业简表（Top3 岗位的职责、工作内容占比、雇主、薪资、风险） | ✅ | 第二章 2.1 |
| 阶段性目标、任务清单、复盘表、SWOT | ✅ | 正文 |
| 计算方法（归一化、Fit 公式、路径权重） | ✅ | 附录（一页） |
| 逐题作答与归一化得分 | ❌ | `原始作答明细.csv` |
| 维度标准差、题内区分度 | ❌ | `维度与适配度.csv` |
| 各岗位适配度分项（兴趣/能力/锚的分数） | ❌ | `维度与适配度.csv` |
| 门槛筛选规则、置信度阈值（<5 分）、计时阈值（<3 秒） | ❌ | 不导出（工具的说明书，不是本人的规划） |
| 任务工时与周数的推算过程 | ❌ | 不导出（内部排期参数） |

**测试锁定的约束**（`测试/smoke.cjs`）：报告正文不得出现"归一化得分""题内标准差""是否反向计分""标准差 < 8""分差 < 5 分""3 秒""按每周"等字样，正文数字密度须低于附录，长度须小于 16,000 字符。当前实测约 **8,400 字符 / 320 行**。

## 八、职业简表：替代生涯人物访谈

**生涯人物访谈已于 v0.2 移除。** 移除理由：时间成本高，且学生不一定能找到合适的从业者，不适合作为必做作业。

它原本要回答的两个问题改由**岗位库**承担：

| 原访谈问题 | 现在的来源 |
|---|---|
| 这份工作实际在做什么 | `job.duties` + `job.workMix`（一周工作内容时间分配） |
| 实际代价是什么 | `job.risks` + `job.workMix` |

**`workMix` 字段**：一周里「写代码/做技术、开会/对齐、写文档/报告、沟通协调」四项的百分比，**合计必须为 100**（由 `测试/契约.test.js` 强制校验）。这是课程设计的重点，因为它回答一个公开资料很难说清的问题。典型的认知偏差：

- 算法研究员：写文档/报告 **40%**、写代码 35%——不是整天写代码，而是在读论文与产出结论
- AI 产品经理：开会 35% + 写文档 35%——主要工作不是"想创意"
- 大模型应用工程师：写代码 65%——多数岗位是把现成模型接进业务链路，很少训练模型

报告第二章会自动为 **Top 3 岗位**生成「职业简表」，并对每个岗位给出一句"最容易误解的地方"（`CP.report.textFor('digestHint')`，按 `workMix` 自动选择措辞）。

**排名较高职业的展开**另有 `jobDigestHead / jobDigestRows`，以及三个辅助函数：

- `CP.report.workMixText(job)`：按占比从高到低输出完整分配
- `CP.report.workMixTop(job)`：占比最高的项，**处理并列**（返回 `{top: [...], max, tied}`）
- `CP.report.nonCodePct(job)`：非技术事务合计占比，用于"有多少时间不在写代码上"

如果学生**自愿**完成访谈，写进报告正文即可，评分量规里作为加分项。

## 九、差距 → 学习任务映射

### 6.1 排序口径随年级切换

```
高年级：priority = severity = ω_k × (gap_k / 100)²        → 缺口越大越靠前
大一  ：priority = 0.25 + 0.75 × interestFit_k            → 与兴趣方向越贴合越靠前
```

- `interestFit_k` 由 `CP.dimInterestFit` 计算：把兴趣六维按强弱归一为权重，乘以"该岗位对这一兴趣方向的看重程度"（岗位兴趣画像 / 该岗位最大值），再按 `CP.ABILITY_DIM_INTEREST` 的能力↔兴趣映射加权汇总。
- `CP.ABILITY_DIM_INTEREST` 是本工作台的**教学假设**，不是心理学结论。例如算法建模主要服务研究型 I（0.7）与常规型 C（0.3）。
- **为什么不按"好补"排序**：那条路会导致大一学生先去补最容易的项，把最难但最关键的（如数学）无限期推迟。按兴趣贴合度排序则兼顾两件事——它偏向前置基础（因为基础课与兴趣方向直接相关），同时保证补的东西是他愿意坚持的。

### 6.2 大一的第 1 条任务永远是"方向探索"

`CP.exploreTask` 插入的任务要求：按兴趣第一名的方向做一个**小到能做完**的东西，并写一页过程记录（卡点 + "还想不想继续"的判断）。验收作品是一个能演示的小作品和一页记录，工时按自主学习自评分数决定 4 或 6 周。

它的目的不是学技术，而是**把兴趣从测评结论变成一个被验证过的事实**。这是大一阶段性价比最高的动作。

### 6.3 映射表的统一要求

差距清单取首位岗位的拖累项（大一为 3 条能力任务 + 1 条探索任务），每条按 `逻辑/建议.js` 的 `TASK_MAP` 映射为：

| 输出项 | 要求 |
|---|---|
| 学习任务 | 必须是**可执行动作**，不是"多读书" |
| 验收作品 | 每项能力缺口至少对应一个可检查的作品 |
| 预计工时 | 用于换算排期周数（按每周 8 小时估） |
| 参考资源 | 具体到书名/章节/课程 |

设计原则：**没有验收作品的建议不进入行动计划**。理由是职业生涯规划最常见的失败不是"不知道要努力"，而是"努力了但无法判断是否有进展"。

## 十、版本迁移

`CP.migrate(obj)` 在导入档案时执行：

- 校验 `kind`，不是本工作台的文件会被拒绝
- 以空白档案为模板补齐缺失字段（例如旧版本没有 `reviews`）
- `computed` 一律置空，强制按新数据重算
- `schemaVersion` 更新为当前版本

**不兼容的结构变更必须先递增 `schemaVersion` 并在此处加迁移分支。**
